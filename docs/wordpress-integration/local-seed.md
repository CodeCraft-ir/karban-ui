# دادهٔ اولیهٔ مجاز — فقط WordPress لوکال

کاربر ابتدا «لوکال، فقط دسته و شهر» را انتخاب کرد، سپس با ارائهٔ فایل Word، ساخت کاربران و پروفایل‌های اولیه را هم برای همین لوکال درخواست کرد. مقصد آنلاین همچنان مجاز نشده است. فایل Word هویت یا شمارهٔ واقعی ندارد؛ طرح کاربران فقط نمونه‌های آشکارِ آزمایشی است، نه اشخاص واقعی.

## محتوای مبتنی بر Word

فهرست قابل بازبینی: [local-taxonomies.json](../../scripts/wordpress/local-taxonomies.json).

- ۱۸ دسته از متن سند، از جمله اخذ پروانه، طراحی و نظارت، معماری، سازه، نقشه‌برداری، تأسیسات، مصالح، تجهیزات و مقاوم‌سازی. عنوان‌ها با اصلاح نگارشی و slugهای فنی انگلیسی آماده شده‌اند؛ این‌ها ساختار قطعی سلسله‌مراتبی نمودار Word نیستند.
- `city` فعلاً خالی است، چون شهر در فایل ذکر نشده؛ فهرست قبلی ۸ شهر اعمال نشده بود و با این ورودی منبع‌محور جایگزین شد.
- پیش‌نویس [local-profile-drafts.json](../../scripts/wordpress/local-profile-drafts.json): یک کارفرمای آزمایشی و سه متخصص آزمایشی معماری/تأسیسات مکانیکی/برقی. بدون مدیر، شماره، ایمیل، نشان تأیید، سابقه، نظر و امتیاز ساختگی.
- **پیش‌نویس کاربران هنوز importer اجرایی ندارد و هیچ حسابی ایجاد نشده است.** ابزار CLI فعلی فقط taxonomyها را ثبت می‌کند. ساخت حساب‌ها پس از رفع اتصال دیتابیس، با رمز تصادفی غیرقابل‌نمایش و بدون ارسال ایمیل/SMS باید جداگانه پیاده و آزموده شود.

## وضعیت واقعی

**هنوز در دیتابیس ثبت نشده است.** در این نشست bootstrap خط فرمان PHP با پیام `Error establishing a database connection` متوقف شد؛ درخواست HTTP همان نصب از طریق Apache موفق است. علت اختلاف CLI/Apache هنوز تشخیص داده نشده؛ رمز/فایل پیکربندی یا سرویس دیتابیس تغییر نکرده و از محدودیت دسترسی عبور داده نشده است.

WP-CLI نصب نیست و مرورگر آزمون نیز session مدیر ندارد. ابزار داده‌گذاری تنها فایل CLI است؛ endpoint عمومی یا راه میانبر احراز هویت اضافه نشده است. فایل‌های زیر بیرون از webroot پروژهٔ WordPress نگهداری می‌شوند.

## پیش‌نمایش و اجرا

پس از رفع تفاوت اتصال دیتابیس PHP خط فرمان با Apache، ابتدا فقط پیش‌نمایش را اجرا و خروجی را بررسی کنید:

```bash
/Applications/XAMPP/xamppfiles/bin/php '/Users/binam/project/پرهیزکاری/karban-uiux/web/scripts/wordpress/seed-local-taxonomies.php'
```

فقط پس از موفقیت پیش‌نمایش و تطبیق مقصد لوکال، ثبت داده‌ها:

```bash
/Applications/XAMPP/xamppfiles/bin/php '/Users/binam/project/پرهیزکاری/karban-uiux/web/scripts/wordpress/seed-local-taxonomies.php' --apply
```

این دو دستور در این مرحله برای ثبت واقعی اجرا نشده‌اند. ابزار مسیر ثابت `/Applications/XAMPP/xamppfiles/htdocs/karban` و `home_url` با میزبان loopback و مسیر `/karban` را کنترل می‌کند؛ مقصد آنلاین را نمی‌پذیرد. تغییر این محافظ‌ها برای اتصال به production مجاز نیست.

- اجرای بدون `--apply` چیزی درج نمی‌کند.
- نام/slug موجود دوباره ایجاد یا بازنویسی نمی‌شود.
- حذف term، تغییر تنظیمات، کاربران یا پست‌ها انجام نمی‌شود.
- شکست درج می‌تواند داده‌های درج‌شدهٔ قبلی همان اجرا را باقی بگذارد؛ موفقیت کامل ادعا نمی‌شود. پس از بررسی، اجرای دوباره بدون ساخت تکراری ممکن است.
- بکاپ معمول محیط توسعه پیش از نوشتن داده توصیه می‌شود. اسکریپت را به هاست آنلاین یا پوشهٔ قابل دسترسی HTTP منتقل نکنید.

## آزمون محلی ابزار

تست مستقل با stubهای WordPress و بدون دیتابیس اجرا شد. RED: پیاده‌سازی خالی در انتظار پیش‌نمایش شکست خورد؛ GREEN: کنترل مقصد/manifest، پیش‌نمایش بدون write، درج و اجرای دوبارهٔ بدون تکرار پاس شدند.

```bash
/Applications/XAMPP/xamppfiles/bin/php '/Users/binam/project/پرهیزکاری/karban-uiux/web/tests/wordpress/local-taxonomy-seed.test.php'
```

پاس‌شدن این تست به معنی ثبت واقعی داده نیست. بعد از اجرای واقعی باید endpoint دسته/شهر و گزینه‌های فرانت دوباره بررسی شوند؛ اجرای ابزار فعلی متخصص نمی‌سازد، چون فقط واردکنندهٔ taxonomy است. مجوز جدید کاربران/پروفایل‌های آزمایشی، به معنی ساخته‌شدن آن‌ها نیست.
