# دادهٔ اولیهٔ مجاز — فقط WordPress لوکال

کاربر ابتدا «لوکال، فقط دسته و شهر» را انتخاب کرد، سپس با ارائهٔ فایل Word، ساخت کاربران و پروفایل‌های اولیه را هم برای همین لوکال درخواست کرد. مقصد آنلاین همچنان مجاز نشده است. فایل Word هویت یا شمارهٔ واقعی ندارد؛ طرح کاربران فقط نمونه‌های آشکارِ آزمایشی است، نه اشخاص واقعی.

## محتوای مبتنی بر Word

فهرست قابل بازبینی: [local-taxonomies.json](../../scripts/wordpress/local-taxonomies.json).

- ۱۸ دسته از متن سند، از جمله اخذ پروانه، طراحی و نظارت، معماری، سازه، نقشه‌برداری، تأسیسات، مصالح، تجهیزات و مقاوم‌سازی. عنوان‌ها با اصلاح نگارشی و slugهای فنی انگلیسی آماده شده‌اند؛ این‌ها ساختار قطعی سلسله‌مراتبی نمودار Word نیستند.
- محدودهٔ اولیهٔ واقعاً ثبت‌شده فقط «کاشان» بود. manifest فعلی CLI/admin هفت شهر کاشان، مشکات، برزک، نیاسر، قمصر، جوشقان قالی و کامو و چوگان را به‌عنوان مبنای تاریخی **۲۰۱۶، غیرجامع و نه تقسیمات رسمی فعلی** دارد؛ از فایل Word استخراج نشده‌اند. metadata نوع `city`، شهرستان `kashan`، `source_year=2016` و `source=application-historical-2016-baseline` حفظ شده است. این گسترش هنوز اعمال نشده؛ آران‌وبیدگل و حدس راوند/فین یا روابط بخش/دهستان اضافه نشده‌اند.
- پیش‌نویس [local-profile-drafts.json](../../scripts/wordpress/local-profile-drafts.json): یک کارفرمای آزمایشی و سه متخصص آزمایشی معماری/تأسیسات مکانیکی/برقی. بدون مدیر، شماره، ایمیل، نشان تأیید، سابقه، نظر و امتیاز ساختگی.
- **هیچ حسابی ایجاد نشده است.** ابزار CLI همچنان فقط taxonomyها را ثبت می‌کند. importer مجزای admin-only در افزونهٔ فعال پیاده شده و در Task 7A با fixture آزموده شده است، نه با اجرای واقعی WordPress. حساب‌های بدون شماره فقط نمایشی و **غیرقابل ورود با OTP** هستند؛ رمز تصادفی نمایش داده نمی‌شود و هیچ شماره/نگاشت مخفی به persona ساخته نمی‌شود.

## وضعیت واقعی

**taxonomyهای اولیه در دیتابیس لوکال ثبت شده‌اند:** ۱۸ دستهٔ خدمات و شهر کاشان با `--apply` درج شدند و خروجی برای همهٔ موارد `created` بود. هیچ کاربر، پروفایل، پروژه، موجودی، پیام یا پرداختی ساخته نشده است.

در اجرای CLI هشدار `Constant DB_HOST already defined` از `wp-config.php` باقی ماند؛ با وجود آن، WordPress bootstrap و درج taxonomy موفق شد. تعریف تکراری `DB_HOST` باید توسط اپراتور در فایل `wp-config.php` حذف شود؛ رمز یا مقدار صحیح آن نباید در گفتگو ارسال شود.

WP-CLI نصب نیست و مرورگر آزمون session مدیر ندارد. ابزار داده‌گذاری فعلی فقط taxonomyها را ثبت می‌کند؛ endpoint عمومی یا راه میانبر احراز هویت اضافه نشده است. فایل‌های زیر بیرون از webroot پروژهٔ WordPress نگهداری می‌شوند.

## مسیر رسمی پیشخوان (Task 6A)

نسخهٔ فعال افزونه اکنون صفحهٔ **نهان → توسعهٔ محلی** را برای مدیر دارای `manage_options` ثبت می‌کند. این صفحه فقط ابزارهای admin-only زیر را ارائه می‌کند:

- پیش‌نمایش کامل manifest نسخه‌دارِ ۱۸ دسته و هفت شهر تاریخی کاشان، چهار حساب و سه پروفایل، نام/slug/نقش و metadata در همان صفحه render می‌شود؛ پیش‌نمایش و نتایج جداگانه به مدیر جاری، hash/version و URL نصب local bind می‌شوند و با تغییر آن‌ها نمایش/اعمال نمی‌شوند. ذخیرهٔ گزارش تنها write مسیر preview مدیریتی است؛ خود preflight seed بدون write است.
- ارتقای صریح و جداگانهٔ schemaهای OTP، refresh credential provenance/InnoDB و مالی. نتیجهٔ هر گام مستقل گزارش می‌شود؛ engine نامناسب یا تعارض مالی به بررسی دستی می‌رود.
- اعمال seed فقط با POST، nonce، دروازهٔ local + `NAHAN_LOCAL_DEV_SEED` و تایید دقیق `I_UNDERSTAND_LOCAL_DEMO` پس از preview همان مدیر. بازبینی کامل دوباره قبل از write انجام می‌شود.

این handlerها عمومی یا REST نیستند، GET mutation ندارند، رمز/راز/تماس را نمایش نمی‌دهند و ارسال `wp_mail`/HTTP را فقط در محدودهٔ apply و با cleanup در `finally` مهار می‌کنند. Task 7A نتایج امن هر ارتقای مستقل، completed items، وضعیت partial، نقطهٔ شکست و راهنمای preview/retry صریح را برای همان مدیر نمایش می‌دهد؛ exception خام یا SQL ذخیره/نمایش نمی‌شود.

پیوند پروفایل نمونه در هر سه جهت بررسی می‌شود: `post_author`، user-meta `nahan_specialist_post` و profile-meta `user`. فقط رکورد یکتای seed-marked با مالک معتبر و پیوند یا تخصیص خالی می‌تواند در preview به `repair` برسد و با apply صریح اصلاح شود؛ نقش اضافه، مالک/اشاره‌گر متعارض، duplicate و رکورد unmarked رد می‌شوند. نام، متن، slug، وضعیت انتشار و taxonomy غیرخالیِ ویرایش‌شده بازنویسی نمی‌شوند. شکست marker اولیه ممکن است رکورد unmarked باقی بگذارد: adopt خودکار مجاز نیست و بررسی دستی لازم است.

تفاوت CLI/admin: CLI فقط name/slug taxonomy را درج می‌کند؛ حساب، پروفایل و metadata term نمی‌سازد. admin برای شهر **جدید** provenance ثبت می‌کند؛ metadata کاشان/term موجود را بازنویسی نمی‌کند. شکست provenance شهر جدید نیازمند بررسی دستی است؛ repair Task 7A مخصوص پیوند/تخصیص خالی پروفایل و marker نمایشی حساب یکتاست، نه بازنویسی term موجود.

اجرای migration یا seed واقعی در Task 6A/7A انجام نشده است؛ مدیر باید پس از بازبینی مستقل و snapshot دیتابیس، وضعیت محیط و preview را خودش بررسی کند.

## پیش‌نمایش و اجرای قدیمی taxonomy CLI

پس از رفع تفاوت اتصال دیتابیس PHP خط فرمان با Apache، ابتدا فقط پیش‌نمایش را اجرا و خروجی را بررسی کنید:

```bash
/Applications/XAMPP/xamppfiles/bin/php '/Users/binam/project/پرهیزکاری/karban-uiux/web/scripts/wordpress/seed-local-taxonomies.php'
```

فقط پس از موفقیت پیش‌نمایش و تطبیق مقصد لوکال، ثبت داده‌ها:

```bash
/Applications/XAMPP/xamppfiles/bin/php '/Users/binam/project/پرهیزکاری/karban-uiux/web/scripts/wordpress/seed-local-taxonomies.php' --apply
```

این دو دستور در این مرحله برای ثبت واقعی اجرا نشده‌اند. ابزار مسیر ثابت `/Applications/XAMPP/xamppfiles/htdocs/karban` و `home_url` با میزبان loopback و مسیر `/karban` را کنترل می‌کند؛ مقصد آنلاین را نمی‌پذیرد. تغییر این محافظ‌ها برای اتصال به production مجاز نیست.

- اجرای بدون `--apply` چیزی درج نمی‌کند.
- نام/slug موجود دوباره ایجاد یا بازنویسی نمی‌شود.
- حذف term، تغییر تنظیمات، کاربران یا پست‌ها انجام نمی‌شود.
- شکست درج می‌تواند داده‌های درج‌شدهٔ قبلی همان اجرا را باقی بگذارد؛ موفقیت کامل ادعا نمی‌شود. پس از بررسی، اجرای دوباره بدون ساخت تکراری ممکن است.
- بکاپ معمول محیط توسعه پیش از نوشتن داده توصیه می‌شود. اسکریپت را به هاست آنلاین یا پوشهٔ قابل دسترسی HTTP منتقل نکنید.

```bash
/Applications/XAMPP/xamppfiles/bin/php '/Users/binam/project/پرهیزکاری/karban-uiux/web/tests/wordpress/local-taxonomy-seed.test.php'
```
