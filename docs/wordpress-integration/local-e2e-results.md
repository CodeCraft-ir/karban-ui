# آزمون واقعی فرانت → WordPress لوکال — ۲۰۲۶-۱۰-۱۸

## تنظیم فقط برای preview

- Next: `http://localhost:3002`
- WordPress: `http://localhost/karban/`
- `WORDPRESS_PERMALINK_MODE=plain`
- متغیرها در entry آزمایشی `.claude/launch.json` به process داده شده‌اند؛ فایل `.env` یا secret تغییر نکرده است. حالت پیش‌فرض استقرار آنلاین همچنان `pretty` است.

## نتایج اجراشده پس از اصلاح

| سناریو | نتیجهٔ واقعی |
|---|---|
| خانه `/` با loader سروری | موفق؛ فرم و بخش دسته‌ها و فهرست نمایش داده شد؛ پیام unavailable حذف شد |
| دادهٔ دسته‌ها | پاسخ واقعی خالی پذیرفته شد؛ «دسته‌بندی منتشرشده‌ای برای نمایش وجود ندارد» |
| دادهٔ متخصص‌ها | پاسخ واقعی ۰؛ «متخصصی پیدا نشد» بدون دادهٔ نمونه |
| ارسال فرم خانه با `برق` | به `/search?q=…` رفت؛ مقدار در فرم جستجو حفظ شد |
| اعمال checkbox نشان تأیید | URL شامل `verified=1` شد؛ checkbox و عبارت جستجو حفظ شدند؛ نتیجهٔ واقعی خالی، نه خطای سرویس |
| sitemap از خود Next | HTTP 200، XML معتبر، دو URL ثابت و بدون slug ساختگی؛ canonical پایه هنوز تنظیم پیش‌فرض پروژه است و باید پیش از deployment بررسی شود |
| پروفایل با slug آزمایشیِ ناموجود | HTTP 404 واقعی؛ نه حالت unavailable/موفقیت جعلی |
| عرض ۳۲۰ پیکسل | scrollWidth=320، بدون overflow افقی؛ فیلترها و حالت خالی باقی ماندند |
| تم روشن | تغییر کلاس تم به light تأیید شد؛ تم تیره نیز قبل از آن فعال بود |
| console error | در بررسی پایانی چیزی گزارش نشد |

اندازهٔ viewport پس از تست به desktop برگشت. سرور آزمایشی Next در پایان این ثبت هنوز فعال بود.

## تفکیک اتصال محیط‌ها

curl از sandbox پوسته اتصال localhost برقرار نکرد، اما process بومی preview Node واقعاً به WordPress XAMPP درخواست فرستاد و پاسخ گرفت. smoke خواندنی شامل REST پلاگین، taxonomyهای core و GraphQL بود. مسیر pretty فعلاً از Apache 404 می‌دهد؛ مسیر plain به‌صورت صریح انتخاب شده است، نه fallback پنهان یا proxy آزاد.

## محدودیت‌ها

- دادهٔ اولیه هنوز درج نشده است؛ PHP CLI bootstrap خطای اتصال دیتابیس داد.
- هیچ پروفایل موجود برای تست نمایش غیرخالی، تماس یا گالری وجود نداشت؛ نتیجهٔ خالی موفق معادل آزمون پروفایل واقعی نیست.
- هیچ SMS، حساب، upload، پروژه، پیام، پرداخت یا mutation در این آزمون‌های صفحات ایجاد نشد.
- کنترل bound صفحه‌بندی/sitemap در بازبینی UI به‌عنوان اصلاح لازم مطرح شده و پیاده‌سازی اصلاح آن جداگانه در جریان است؛ موفقیت دیتابیس خالی این ریسک در دادهٔ بزرگ را رد نمی‌کند.
- حالت plain/پذیرش taxonomy خالی با ۱۵۰ تست Node و TypeScript/lint گزارش موفق دارد؛ بازبینی امنیت آن جداگانه در جریان است.
- سایت آنلاین و FTPS دست‌نخورده‌اند؛ رمز FTP در کد، فرمان، تنظیمات یا گزارش ذخیره نشده است.
