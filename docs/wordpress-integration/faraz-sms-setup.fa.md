# تنظیمات فراز SMS در WordPress لوکال

## وضعیت تأییدشده

driverپترن Faraz/IPPanel و ذخیرهٔ امن تنظیمات در سطح source/offline test بازبینی شدند. آزمون20/20 مورد جدید،11مجموعهPHPقبلی وlint65فایل گزارش موفق دارد. بازبینی مستقل، مغایرت اعتبارسنجی rawkey پیش ازtrimWordPress را بسته و Important/Critical باقی‌مانده‌ای در محدوده پیدا نکرد.

بررسی خواندنیِ صفحهٔ واقعی مدیریت نیز انجام شد: پنج فیلد زیر موجودند؛ فیلدAPIkey ازنوعpassword، autocompleteoff و valueرندرشدهخالی است. هیچ فرم تنظیمات ارسال، کلید خوانده یا پیامک صادر نشد.

## محل ورود اطلاعات

لوکال: `http://localhost/karban/wp-admin/admin.php?page=nahan-settings`

- **درایور پیامک:** `faraz_ippanel`، دقیق و بدون فاصله.
- **Faraz / IPPanel API Key:** کلید دسترسی پنل خودتان؛ در گفتگو یا فایل پروژه قرار ندهید. درروشاینadapterنامکاربری/رمزلازم نیست.
- **Faraz Pattern Code:** شناسهٔ پترن تأییدشدهٔ ارسالOTP، نه خودکدیکبارمصرف.
- **Faraz Originator (E.164):** شمارهٔ فرستندهٔ مجازِ واقعی پنل در قالبE.164؛ مقدار را ازپنل بگیرید، حدس نزنید.
- **Faraz OTP Variable:** نام دقیق متغیر پترن؛ `code` فقط وقتی درست است که متغیر پترن شما همین نام را دارد.

کلید ذخیره‌شده درHTML بازگردانده نمی‌شود؛ ورودی خالی/ارسال‌نشده، مقدار قبلی را نگه می‌دارد. حذف با intentصریحِ کنترلپاک‌کردن است. فاصله/خط‌جدید درکلید به‌عنواناشتباه رد می‌شود، نه اصلاحخودکار. گزینه‌های SMS با sanitize/capability/nonce وautoloadغیرفعال ذخیره می‌شوند؛ ادعای encryptionجدید برایoptionsنشده است.

## مهم: هنوز SMS واقعی را تست نکرده‌ایم

ورودمحلی فعلاً gateکدثابت145632را دارد و SmsServiceدرآنمسیر فراخوانی نمی‌شود. صرفذخیرهٔ APIkey به معنی ارسال OTPواقعی نیست. modeصریح، readiness وopt-inجداگانهٔ Next/WordPress اکنون درکدپیاده‌سازی و مستقل تأیید شده‌اند (PHP13مجموعه،Node300،tsc/lint/offlinebuild گزارش موفق). هیچ حالت واقعی یا پیامکی توسط این تأیید فعال نشده است.

### فعال‌سازی کنترل‌شده پس از ذخیرهٔ اطلاعات

1. مقادیر Faraz را در همین صفحهٔ مدیریت ذخیره کنید؛ driverباید `faraz_ippanel` باشد و Pattern/Originator/Variable واقعیپنل را ازخودپنل بگیرید. کلید را درگفتگو نفرستید.
2. دربخش مستقل «پیامک واقعی محلی»، پس ازخواندن هشدار هزینه وکول‌داون، عبارت `ENABLE_REAL_SMS` را خودتان وارد و «فعال‌سازی پیامک واقعی محلی» را بزنید. این اقدامcapability+POST+nonce جدا، gateمحلی وprovider/schema readiness را کنترل می‌کند و پیامک نمی‌فرستد.
3. فعال‌سازی، challenge/نشست‌های صادرشده باکدثابت را نامعتبر می‌کند؛ آن‌ها بهSMSواقعی تبدیل نمی‌شوند. sessionمدیرعادیWordPress بااینJWTمحلی یکی نیست.
4. readiness واقعی باید mode=`sms`،codeLength=5،otpSchemaReady=true،credentialSchemaReady=true،providerConfigured=true وlocalRealSmsAllowed=true باشد. این‌ها فقط آمادگیپیکربندی‌اند، نه تضمیناعتبارکلید/موجودی/تحویل.
5. مستقل ازPHP، Next به `KARBAN_ALLOW_LOCAL_SMS=true` درenvخصوصی نیاز دارد؛ base `KARBAN_LOCAL_DEVELOPMENT=true`،origin/محیطlocal نیزلازم‌اند. تاoperatorعمداًmodeرافعالونتیجه‌اش تأییدنشده، این flagاضافهیاtrueنشود؛ مقدارغایب/false قبل ازOTPحالتSMSرا503می‌کند و پیامکی صادرنمی‌شود.
6. بعد ازتطابقهردوreadiness، فقط یکبارفرم ورود با شمارهٔ تحتکنترل خودتان وکدتصادفی واقعی دریافتی آزموده شود. کدثابت145632 دراینحالت نیست؛ OTPواقعیپنج‌رقمی است. هیچ گیرنده‌ای ازحساب‌ها استخراج/حدس زده نمی‌شود.

خاموش‌کردن ازعملیات مستقل «خاموش کردن پیامک واقعی محلی» و سپس حذف/falseکردن opt-inNext انجاممی‌شود؛ بازگشتکدثابت فقطاگرگیت‌هایقبلی سالمباشند. خطا/timeout خودکار تکرار یا دورزدنکول‌داون ندارد. کدموضوعی را صرفاً برای دورزدنreadiness تغییرندهید.

پس ازتکمیل وبازبینیpolicy، یکآزمون واقعی کنترل‌شده فقط با شمارهٔ تحتکنترل اپراتور و انتخابصریح ارسال انجام می‌شود. APIacceptance تحویلپیامکنیست؛ رسیدنپیامکوورودباهمانکدتصادفی جداگانه تأیید می‌شود. خطا/timeoutخودکارتکرارSMSیاfallbackبهlog/کدثابتندارد.

ارسالپترن ازHTTPSثابت `https://edge.ippanel.com/v1/api/send` وکلیدسرورانجاممی‌شود؛ وب‌سرویسloginپنلبرایOTPکاربراناشتباهگرفتنمجازنیست. سازگاریهمینکلید/حساب/پترن باآداپتربایددرآزمونواقعی بعدی ثابتشود، نه ازوجودفیلدهایپنل.
