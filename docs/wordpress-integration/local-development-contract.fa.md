# قرارداد توسعهٔ لوکال کاربان — کاشان

## درخواست تأییدشده

- فقط **شهرستان کاشان** و محل‌های معتبرِ زیرمجموعه؛ آران‌وبیدگل خارج از محدوده است.
- ورود آزمایشی با کد شش‌رقمی `۱۴۵۶۳۲` چون SMS فعال نیست.
- پرداخت موفق آزمایشی چون درگاه فعال نیست، با ثبت واقعی state و اعمال واقعی اثر در WordPress لوکال.
- دادهٔ اولیه و کاربران/پروفایل‌های آزمایشی بر اساس دسته‌های فایل Word، با برچسب واضح آزمایشی.
- فرانت مستقل Next.js و WordPress به‌عنوان مرجع داده و مجوزها.

**این سند طراحی و معیار اجراست، نه اعلام پیاده‌شدن OTP، پرداخت یا seed.**

## مرز امن حالت توسعه

حالت آزمایشی به‌صورت پیش‌فرض خاموش است. فعال‌سازی باید در تنظیم سرور، فقط با محیط WordPress نوع local و URL نصب loopback ممکن باشد. Host/forwarded header یا payload کاربر نمی‌تواند آن را روشن کند. endpointهای توسعه برای peer غیرمحلی رد می‌شوند و Next dev به loopback محدود می‌ماند. انتقال همین کد به سایت آنلاین نباید کد ثابت یا پرداخت شبیه‌سازی‌شده را فعال کند.

## OTP

- کد ثابت در **سرور WordPress** و از مسیر تولید challenge ایجاد می‌شود؛ فرانت آن را با شرط محلی قبول نمی‌کند.
- tracking، hash، انقضا، سقف درخواست/تلاش و مصرف اتمیک یک‌باره باقی می‌مانند.
- طول و نوع challenge ثبت می‌شوند؛ تولیدی پیش‌فرض تصادفی پنج‌رقمی و local توسعه شش‌رقمی است.
- خاموش‌شدن حالت توسعه باید challenge/credential توسعه را نامعتبر کند، نه به ورود تولیدی تبدیل نماید.
- هیچ SMS واقعی یا log حاوی OTP/شماره فرستاده نمی‌شود.
- نقش حساب موجود هرگز با پارامتر نقش ثبت‌نام عوض نمی‌شود.
- JWT/refresh تنها در مرز امن سرور و نشست معتبر نگه داشته می‌شوند؛ نه localStorage، Zustand یا پاسخ عمومی.

## پرداخت

- provider با نام صریح آزمایشی، بدون تماس با بانک.
- initiate احرازشده با مبلغ معتبر تومانی، هدف معتبر و رکورد pending واقعی.
- confirm فقط توسط مالک، POST معتبر و دروازهٔ local؛ مبلغ/نقش/هدف از رکورد تثبیت‌شده، نه ورودی قابل تغییر.
- transition و fulfillment تراکنشی و تکرارناپذیر؛ دوبار کلیک یا retry فقط یک credit/debit/unlock ایجاد می‌کند.
- نتیجه از endpoint رکورد متعلق به کاربر خوانده می‌شود؛ `?status=success` مجوز یا سند پرداخت نیست.
- صفحه با عنوان «پرداخت آزمایشی موفق — بدون انتقال وجه» فقط پس از commit موفق نمایش داده می‌شود.
- موجودی یا شمارهٔ تماس از state ساختگی فرانت نمی‌آیند؛ تماس مشتری فقط پس از entitlement.

## جغرافیا و seed

- فهرست کامل شهر/روستا باید منبع و نسخهٔ قابل بررسی داشته باشد؛ فایل Word چنین فهرستی ندارد.
- کاشان محدودهٔ تأییدشدهٔ کاربر است؛ نسبت روستا/بخش/دهستان از روی نزدیکی یا حدس ساخته نمی‌شود.
- نوع محل و رابطهٔ آن سمت سرور معتبر باشد؛ شهر/روستا با محله یکی نیست.
- انتخاب خارج محدوده در API پروفایل، پروژه و جست‌وجو نیز رد می‌شود.
- کاربران اولیه با marker و کلید مشخص، نقش غیرمدیر و رمز تصادفی غیرقابل‌نمایش؛ بدون پیام خارجی، هویت واقعی ساختگی، verified، امتیاز و نظر جعلی.
- نمایش پروفایل نمونهٔ منتشرشدهٔ local باید آشکارا «آزمایشی» باشد. هیچ دادهٔ آزمایشی به سایت آنلاین منتشر نمی‌شود.
- seed preview بدون write؛ preflight کامل و اجرای دوباره بدون تکرار. تعارض با کاربر واقعی باعث توقف است، نه overwrite.

## وضعیت و پیش‌نیازهای واقعی

- اتصال عمومی لوکال، خانه/جست‌وجو/فیلتر/sitemap/404 آزموده شده است؛ آخرین suite گزارش‌شده ۱۵۳ تست موفق و build با Webpack موفق است.
- نشست کامل و handlerهای auth هنوز اجرا نشده‌اند؛ `iron-session` نصب نیست و registry فعلاً در این نشست مسدود است. رمزنگاری دست‌ساز یا ذخیرهٔ browser token جایگزین نمی‌شود.
- PHP CLI فعلاً به دیتابیس این نصب وصل نمی‌شود؛ HTTP Apache سالم است. هنوز seed یا حسابی ایجاد نشده است.
- مسیر جایگزین مجاز برای seed می‌تواند صفحهٔ رسمی پیشخوان با session مدیر، capability، nonce و gate محیط باشد؛ endpoint عمومی یا فایل bootstrap باز مجاز نیست. ورود مدیر باید توسط صاحب محیط انجام شود، بدون ارسال رمز در گفتگو.
- schema فعلی پرداخت/wallet/lead هنوز atomicity لازم را ندارد؛ قبل از provider آزمایشی به migration نسخه‌دار و کنترل concurrency نیاز دارد. «تست» بودن به معنی مجازبودن موفقیت جعلی نیست.

## معیار پایان

دو نقش → OTP توسعه → نشست → پروژهٔ متعلق به کاربر → شارژ آزمایشی → موجودی واقعی → خرید سرنخ یک‌باره → تماس مجاز → پیام، به‌همراه logout/refresh و آزمون موارد منفی. همه روی لوکال، بدون SMS/بانک/انتشار آنلاین. هر پیش‌نیاز حل‌نشده صریحاً blocked گزارش می‌شود.
