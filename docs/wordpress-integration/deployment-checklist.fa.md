# پیش‌نیازهای اتصال نهایی کاربان

وضعیت ۲۰۲۶-۱۰-۱۶: کاربر اعلام کرده پلاگین karban-core و افزونه‌های لازم روی سایت به‌روزرسانی/نصب شده‌اند. این اعلام، جایگزین آزمون آنلاین قراردادها و تنظیمات نیست. بررسی کد محلی انجام شده؛ دسترسی این نشست به سایت و npm با 403 از proxy مسدود است.

## کارهای لازم در محیط اجرا

1. **فرانت باید روی Node.js مستقل اجرا شود**، نه صرفاً با آپلود فایل‌های static در WordPress. دامنهٔ نهایی فرانت، HTTPS و مقصد بازگشت پرداخت باید هنگام استقرار تنظیم شوند.
2. **دسترسی این محیط به `registry.npmjs.org` و `codecraft.ir:443`** باید از طریق مجازسازی رسمی سیاست شبکه فراهم شود. تغییر WordPress این محدودیت را رفع نمی‌کند. محدودیت نباید با proxy/registry جایگزین دور زده شود.
3. **WPGraphQL و ACF Pro باید فعال باشند**؛ صرف نصب کافی نیست. بررسی واقعی schema هنوز انجام نشده است.
4. **SMS واقعی** را در تنظیمات پلاگین پیکربندی کنید: driver کاوه‌نگار، API key و الگوی پیامک لازم‌اند. driver از نوع `log` برای production مناسب نیست، چون شماره و OTP را در log ثبت می‌کند. کلید یا OTP را در گفتگو نفرستید.
5. **راز JWT قوی و تنظیم TTLها** را از مسیر امن مدیریت WordPress فراهم کنید. این مقادیر در فرانت یا `NEXT_PUBLIC_*` قرار نمی‌گیرند. reverse proxy/وب‌سرور باید header `Authorization` را به PHP منتقل کند.
6. **درگاه زرین‌پال** ابتدا در sandbox با merchant/callback معتبر پیکربندی و آزموده شود. callback در WordPress می‌ماند؛ مقصد نتیجهٔ Next باید allowlist و اطلاعات نتیجه باید مالک‌محور باشد. پارامتر `status` در URL اثبات پرداخت نیست.
7. **نشست Next** هنوز به نصب وابستگی معتبر `iron-session` و تنظیم راز نشست سمت سرور نیاز دارد. هیچ token یا OTP را در localStorage، Zustand، کد HTML یا پاسخ عمومی قرار ندهید.
8. **حساب/محیط آزمایشی مشخص** برای آزمون OTP، آپلود، ثبت پروژه، گفتگو و پرداخت لازم است. این سند اجازهٔ ارسال SMS/پرداخت/ساخت داده در production نیست.

## اصلاحات کدنویسی باقی‌مانده، نه تنظیمات ادمین

این موارد در کد محلی بررسی شدند و صرف نصب افزونه‌ها رفعشان نمی‌کند:

- کنترل انتشار و رمز پروفایل عمومی قبل از نمایش/ثبت بازدید؛ اصلاح محدود محلی و patch آن در حال آماده‌سازی است.
- اعتبارسنجی مالکیت attachment در مصرف‌کنندگان پروژه/پروفایل/پیام، نه فقط ثبت مالک هنگام آپلود.
- API امن خواندن پروژه‌ها و آمار مختص کارفرمای فعلی.
- تراکنش/قفل و تکرارناپذیری خرید سرنخ، debit کیف پول و fulfillment پرداخت؛ endpoint نتیجهٔ پرداخت متعلق به کاربر.
- مصرف اتمیک OTP و چرخش refresh برای جلوگیری از استفادهٔ هم‌زمان.

قبل از انتشار تغییرات backend، نسخهٔ پشتیبان و استقرار کنترل‌شده لازم است. تغییر فایل محلی به معنی نصب آن روی `https://codecraft.ir/kar/` نیست.

## چه چیزی اکنون آزموده شده است؟

- لایهٔ REST/GraphQL و هستهٔ auth با fixtureهای تزریقی، بدون شبکه.
- سرویس‌های عمومی متخصص/دسته‌بندی با آزمون محلی؛ گزارش اجرای کامل فعلی: ۱۳۹ تست موفق.
- TypeScript و scoped lint گزارش موفق دارند.
- build با Webpack در مرحلهٔ قبل موفق شد؛ build پیش‌فرض Turbopack با محدودیت پورت داخلی sandbox متوقف شد.

ورود کامل، فرم‌های متصل، پروژه/کیف پول/پرداخت و آزمون آنلاین هنوز تحویل نهایی نشده‌اند. هیچ commit، push یا deploy بدون درخواست جداگانه انجام نمی‌شود.
